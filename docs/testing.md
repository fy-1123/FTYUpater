# 手工验收清单（E2E）

> 这些是**只能靠人手在真机上跑**的验收项。逻辑层的东西都写成了纯 JVM 单测（`gradlew test`），
> 不需要开游戏；本文档只收「必须开游戏 / 必须有两个进程」的部分。
>
> 状态：**全部未执行**。用户 2026-11-07 明确要求不上真机测试，因此本文档是待办清单，
> 不是已验证记录。谁跑完了，就在对应项后面写上日期与结果。

## 0. 前置准备

```bat
rem 服务端（一个终端）
.\gradlew.bat runServer

rem 客户端（另一个终端）
.\gradlew.bat runClient
```

- 服务端首次启动要生成 `run/config/ftyupater-server.toml`，默认 HTTP 端口 `8081`。
- 客户端首次启动要生成 `run/config/ftyupater-client.toml`。
- 两个进程共用 `run/` 目录，日志会混在一起——看日志时注意区分。
- 确认服务端在跑：浏览器打开 `http://127.0.0.1:8081/api/v1/health`，应返回 JSON。

服务端内容目录（相对 `run/`）：

| 目录 | 作用 |
| --- | --- |
| `mods/` | 服务端模组目录，会**整个镜像**给客户端 |
| `clientpack/` | 只给客户端的文件（config、资源包、光影包等），保留目录结构 |

## 1. 首次进服：需要同步

**目的**：验证「服务器有客户端没有的内容」时，进服会被拦下并给出正确数量。

1. 服务端 `run/mods/` 放一个客户端也需要的 jar（比如随便一个纯客户端模组）。
2. 客户端 `run/mods/` **不要**放这个 jar。
3. 客户端多人游戏 → 连 `127.0.0.1` → 进服。
4. 观察：

- [ ] 弹出「进服前检查」界面，不是直接进服。
- [ ] 界面写明同步源地址、需要安装几个、需要清理几个。
- [ ] 列表里能看到那个 jar 的名字与角色（必需 / 可选）。
- [ ] 按钮为【一键同步】【进入服务器】【取消】。

## 2. 一键同步：文件真的落地

1. 在上一步的界面点【一键同步】。
2. 等待完成，观察报告行。

- [ ] 报告显示安装数 ≥ 1。
- [ ] `run/mods/` 里出现了那个 jar。
- [ ] 文件大小与服务器上的一致。
- [ ] `run/ftyupater/state.json` 里 `generation` 有值，`entries` 里有这个 jar 的 sha256。
- [ ] `run/ftyupater/logs/sync.log` 有对应记录。

## 3. 同步后进服：自动放行

1. 重启客户端（让同步结果生效）。
2. 再次连 `127.0.0.1`。

- [ ] 不再弹检查界面，直接进服（`autoContinueIfInSync` 默认 true）。
- [ ] 若弹出提示，也只是「已一致」类的非阻断信息。

## 4. 服务器加内容：客户端再次被拦

1. 服务端 `run/mods/` 再加一个 jar。
2. 等服务端代际刷新（默认 10 秒扫一次；看服务端日志有「新代际」字样）。
3. 客户端进服。

- [ ] 又被拦下，且「需要安装」数量是 1（只差新增那个）。
- [ ] 之前同步过的文件不在「需要安装」列表里。

## 5. 服务器删内容：客户端清理进回收站

1. 服务端删掉一个之前同步过的 jar。
2. 等代际刷新。
3. 客户端进服 → 一键同步。

- [ ] 报告显示「清理 1」。
- [ ] 客户端 `run/mods/` 里那个 jar 消失了。
- [ ] `run/ftyupater/trash/<时间戳>/mods/<jar>` 里能找到它（**没有真删**）。

## 6. 回收站还原

1. 在「进服前检查」界面点【版本回退】→ 在回退界面点【回收站】。
2. 选中刚才那条清理记录 → 【还原这次清理】。

- [ ] 报告显示「还原 1 个文件」。
- [ ] 文件回到 `run/mods/`。
- [ ] 回收站里那条记录消失（目录空了被清掉）。
- [ ] 如果目标位置已有同名文件，报告显示「跳过 1」且**原文件内容没被覆盖**。

## 7. 被锁定的文件 → pending → helper

**目的**：验证 Windows 上游戏运行中无法替换的 jar，会在退出后由独立进程补上。

1. 客户端保持运行，且已同步过一次。
2. 服务端**更新**那个 jar（换成另一个版本，内容不同 → sha256 不同）。
3. 客户端进服 → 一键同步。

- [ ] 报告里出现「排队 N（重启后生效）」而不是「失败」。
- [ ] `run/ftyupater/pending/pending.json` 里有 `REPLACE` 记录，带目标 sha256。
- [ ] 此时 `run/mods/` 里那个 jar 还是旧版本（被占用，没换成）。

4. **完全退出游戏**（不是退回主菜单，是关掉进程）。
5. 等几秒（helper 轮询父进程退出，间隔 500ms）。
6. 观察 `run/ftyupater/pending/helper-result.jsonl`。

- [ ] 文件存在，且 `type":"finished"` 那行有 `remaining:0`。
- [ ] `run/mods/` 里的 jar 已经是新版本（大小/时间戳变了）。
- [ ] `run/ftyupater/pending/pending.json` 变成空数组 `[]`。
- [ ] 旧版本 jar 在 `run/ftyupater/backup/helper-<时间戳>/` 里。

7. 再启动客户端。

- [ ] 弹出 Toast「重启后已更新」，正文写着替换了几项。
- [ ] 该 Toast 只弹一次（第二次启动不再出现）。

## 8. helper 失败 → 下次启动有提示可重试

1. 制造一个会失败的 pending：把 `run/mods/` 里某个已同步的 jar 用文本编辑器占住（或用 `attrib +R` 设为只读）。
2. 让服务端更新它 → 客户端同步 → 得到 pending。
3. 退出游戏，等 helper 跑完。

- [ ] `helper-result.jsonl` 里出现 `type":"failed"`，且有 `type":"error"` 说明原因。
- [ ] `pending.json` 里那条记录**还在**（`remaining` ≥ 1）。

4. 再启动客户端。

- [ ] 弹出 Toast「上次更新没全部成功」，正文含失败项数与第一条错误。
- [ ] 后台会自动再拉起一次 helper（日志里能看到）。

5. 解除只读，退出再启动。

- [ ] 这次成功，Toast 变成「重启后已更新」。

## 9. 服务器回退：客户端被明说

1. 服务端已有 2 个以上代际（加过内容又删过内容即可）。
2. 服务端把 `mods/` 恢复到较早的状态，使新代际的 `parentGeneration` 指向更早的内容。
3. 客户端进服。

- [ ] 检查界面顶部状态行写明「服务器已回退到更早的版本（…），同步会把本地也退回那一版」。
- [ ] 不是静默当成「没有变化」。

## 10. 客户端主动回退

1. 进服前检查界面 → 【版本回退】。
2. 观察列表。

- [ ] 至少能看到「刚退下来的」那一代，且排在第一位。
- [ ] 每行写明来源（本地备份 / 服务器 / 两者都有）与文件数。
- [ ] 只有本地备份的行，按钮文案带「（本地备份）」。

3. 选中 → 【退回到这个版本】。

- [ ] 报告写明「从服务器还原」或「从本地备份还原」。
- [ ] 走本地备份时，报告追加「可能不完整（新增文件无法删除）」。
- [ ] `run/ftyupater/state.json` 的 `generation` 变成目标代际，`previousGeneration` 是回退前的代际。

4. 再点一次回退，应能退回来（`previousGeneration` 生效）。

- [ ] 能反向退回到刚才那一代。

## 11. 可选模组 opt-out

**目的**：验证「客户端专属、玩家可以不装」的内容，删掉也不影响进服。

服务端 `clientpack/` 下的文件**自动就是 optional**（`ContentScanner.java:128` 写死
`Role.OPTIONAL`），不需要任何额外配置——这是本项能测起来的前提。

1. 服务端 `run/clientpack/config/example-common.toml` 放一个文本文件（内容随便写）。
2. 等代际刷新，客户端进服。

- [ ] 该行出现在列表里，角色标为「可选」。
- [ ] 因为只有可选条目缺失，`DiffResult.blocksJoin()` 为 false → **不拦截进服**，
  只给非阻断提示（这是设计意图，不是 bug）。

3. 若被拦下（说明还有 required 项），点该行的【我不要】。

- [ ] 该行变成「已忽略」，不再计入需要安装。
- [ ] `run/ftyupater/state.json` 的 `optOut` 里有它的相对路径。
- [ ] 再点【恢复】能取消忽略，该行回到待安装。

4. 重新进服（不点一键同步）。

- [ ] 只有 optional 项缺失时仍能进服。

## 12. v1 迁移

**目的**：老版本玩家升级后，旧配置不丢。

1. 在 `run/config/` 里手工造三个 v1 文件：
   - `ftyupater-ignore.txt`：一行 `someclientmod.jar`
   - `ftyupater-pending-deletions.txt`：一行 `oldmod.jar`
   - `ftyupater-last-server.txt`：一行 `127.0.0.1:25566=http://192.168.0.250:8081`
2. 启动客户端。

- [ ] 弹出 Toast「已从旧版本迁移」，正文含忽略 1 / 待删除 1 / 服务器记忆 1。
- [ ] 三个旧文件被改名成 `*.migrated`（**没有删除**）。
- [ ] `run/ftyupater/state.json` 的 `ignored` 里有 `mods/someclientmod.jar`。
- [ ] `run/ftyupater/pending/pending.json` 里有 `DELETE mods/oldmod.jar`。
- [ ] `run/ftyupater/servers.json` 里有 `127.0.0.1:25566`。

3. 再启动一次客户端。

- [ ] 不再弹迁移提示（旧文件已改名，幂等）。
